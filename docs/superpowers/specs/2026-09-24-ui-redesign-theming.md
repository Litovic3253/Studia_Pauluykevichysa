# Mochi Desktop — редизайн UI и светлая/тёмная тема (дизайн)

Дата: 2026-09-24

## Контекст

Mochi Desktop (см. [2026-09-24-desktop-app-design.md](2026-09-24-desktop-app-design.md))
реализован и работает: 6 экранов на чистом Flet без единой темы/стиля —
голые `ft.Column`/`ft.Row` со стандартными полями, один статический
цвет фона, никакой поддержки тёмной темы.

Владелец хочет:
- визуально более современный, «воздушный» интерфейс в духе
  Яндекс.Почты/Диска — мягкие скруглённые карточки и кнопки, минимализм,
  много отступов;
- переключение светлой/тёмной темы — кнопкой в интерфейсе, по умолчанию
  следует системной теме Windows, выбор запоминается между запусками.

Отдельно (уже исправлено, до этого редизайна) была починена утечка
`page.overlay`, из-за которой приложение «зависало» после нескольких
кликов — см. коммит `f129b21`. Редизайн не решает проблем
производительности сам по себе, это чисто визуальная задача.

## Решение

### Общая тема

Новый модуль `app/theme.py` — единая точка правды для всего визуального
языка приложения:

```python
LIGHT_THEME = ft.Theme(color_scheme_seed="#3D5AFE", use_material3=True)
DARK_THEME = ft.Theme(color_scheme_seed="#3D5AFE", use_material3=True)

CARD_RADIUS = 16
BUTTON_RADIUS = 12
SPACING = 16
PAGE_PADDING = 24

def card(content: ft.Control, **container_kwargs) -> ft.Container:
    """Единая обёртка «карточка»: скруглённые углы, поверхностный фон
    темы, мягкая тень, внутренний отступ — используется всеми экранами
    вместо голого Column/Row."""
```

`#3D5AFE` — мягкий синий (тон в духе Яндекс.Диска, а не кричащих
жёлто-красных акцентов Такси/Маркета — так и просил владелец: минимализм
и воздух, а не яркий бренд-акцент). Material 3 (`use_material3=True`)
сам генерирует согласованную светлую/тёмную палитру из этого seed-цвета
через `ColorScheme`, включая цвета поверхностей карточек — не нужно
вручную подбирать десятки оттенков.

### Переключение темы

`app/main.py`:
- `page.theme = LIGHT_THEME`, `page.dark_theme = DARK_THEME`.
- `page.theme_mode` при старте берётся из `db.get_settings()["theme_mode"]`
  (новый ключ в `DEFAULT_SETTINGS` в `db.py`, значение `"system"` по
  умолчанию — работает по той же схеме, что и текущие `currency`,
  `reminder_hour`: одна строка в `DEFAULT_SETTINGS`, `init()` уже сам
  проставляет её через существующий цикл `INSERT OR IGNORE`, никакой
  новой миграции не требуется).
- Кнопка-переключатель (иконка `ft.Icons.BRIGHTNESS_6` в верхней части
  `NavigationRail`, по клику циклически: system → light → dark → system)
  пишет новое значение через `db.set_setting("theme_mode", ...)` и сразу
  применяет `page.theme_mode = ...; page.update()`.

### Карточная вёрстка по экранам

Каждый экран группирует поля в 1–3 логических карточки (через
`theme.card(...)`) вместо плоского списка полей, с отступом `SPACING`
между карточками и `PAGE_PADDING` по краям экрана:

- **Заказы** — карточка фильтров/поиска сверху, список заказов ниже;
  каждая строка заказа — скруглённая карточка-строка вместо голого
  `ListTile`.
- **Карточка заказа** — три карточки: «Заказчик и статус» (статус,
  оплата, клиент/контакт, привязка к клиенту), «Печать и цена»
  (материал/цвет/вес/часы/кол-во/срок/цена), «Вложения» (список +
  кнопка добавить). Кнопка удаления заказа — отдельно снизу, вне карточек,
  чтобы визуально не терялась среди обычных действий.
- **Новый заказ** — две карточки: «Заказчик» и «Параметры печати»
  (материал…срок, предпросмотр цены, вложения).
- **Клиенты** — карточка поиска + список карточек-клиентов; при выборе —
  карточка деталей (контакты, заметки, история заказов).
- **Цены** — карточка «Материалы» (список + добавление) и карточка
  «Ставки» (час печати, реверс-моделирование, валюта).
- **Статистика** — вместо текущего текстового списка: ряд компактных
  карточек-показателей (выручка/прибыль/долг/заказов за месяц — по
  аналогии с тем, как это выглядит в Яндекс.Диске на странице
  хранилища), ниже — карточка с разбивкой по статусам и расходом
  материала. Это заодно закрывает пункт из финального ревью
  предыдущего этапа («Stats screen is a text list, not the spec's
  dashboard») — правим его сейчас, раз уж переделываем визуал этого
  экрана целиком.

### Что не меняется

- Левая `NavigationRail` остаётся — этот вопрос отдельно не поднимался,
  переделка навигации не входит в объём этой задачи.
- Никакой бизнес-логики (расчёт цены, работа с БД, live-sync) не
  трогаем — только представление.

## Тестирование

Автотестов на визуальные детали Flet нет смысла писать (как и раньше —
Flet-деревья не тестируются осмысленно юнит-тестами). Проверяем:
- `app/theme.py`: юнит-тест на `card()` — что возвращает `ft.Container`
  с ожидаемым `border_radius` и что переданный `content` действительно
  попадает внутрь (это чистая функция без побочных эффектов, тестируется
  как обычно).
- Новый ключ `theme_mode` в `db.py`: юнит-тест, что `get_settings()`
  возвращает `"system"` по умолчанию на свежей БД и что `set_setting`
  меняет его — по образцу существующих тестов на `currency`/`hour_rate`.
- Ручная проверка каждого экрана (как в предыдущем плане) — карточки
  отображаются, тема переключается и переживает перезапуск приложения.

## Вне рамок (не делаем сейчас)

- Смена компоновки навигации (боковая → нижняя/верхняя).
- Анимации переходов между экранами.
- Кастомная типографика/шрифты за пределами дефолтной Material 3.
- Оптимизация live-sync-каскада (см. «Контекст») — отдельная задача,
  не текущий редизайн.
