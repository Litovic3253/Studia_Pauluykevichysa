# Электроника в заказах (дизайн)

Дата: 2026-10-14

## Контекст

Студия кроме 3D-печати собирает устройства: ESP32, экраны, светодиодные
ленты и т. п. Корпуса для них печатаются здесь же, поэтому электроника —
не отдельный раздел, а часть заказа. Нужно учитывать себестоимость
компонентов и оплату работы: пайку/сборку и программирование (прошивку).

Решения владельца:
- компоненты — списком внутри заказа, без склада;
- с клиента за компоненты — закупка + наценка в %;
- пайка и прошивка — фиксированными суммами (не часы × ставка);
- в PDF для клиента — каждый компонент отдельной строкой.

## Данные

### Заказ (`orders`) — новые колонки

| колонка | тип | по умолчанию | смысл |
|---|---|---|---|
| `has_print` | INTEGER | 1 | в заказе есть печать |
| `has_electronics` | INTEGER | 0 | в заказе есть электроника |
| `soldering_price` | REAL | 0 | пайка и сборка, ₽ (для клиента) |
| `firmware_price` | REAL | 0 | программирование (прошивка), ₽ |
| `components_markup` | REAL | 0 | наценка на компоненты, % |

Старые заказы после миграции: печать есть, электроники нет, цены не
меняются.

### Новая таблица `order_components`

```
id INTEGER PRIMARY KEY AUTOINCREMENT
order_id INTEGER NOT NULL REFERENCES orders(id)
name TEXT NOT NULL
qty REAL NOT NULL DEFAULT 1
unit_cost REAL NOT NULL DEFAULT 0   -- закупка за штуку, ₽
```

Порядок строк — по `id`. Отдельного справочника нет: подсказки при
вводе названия — `DISTINCT name` из прошлых заказов с последней
`unit_cost` (`db.component_catalog()`).

Компоненты:
- переносятся вместе с заказом в `renumber_order`;
- удаляются в `delete_order` и в `delete_customer(delete_orders=True)`;
- учитываются в `change_fingerprint()` (live-обновление экрана);
- в GitHub уходят вместе с файлом базы — отдельной работы нет.

### Настройки

`components_markup` — наценка на компоненты по умолчанию, % (20).
Подставляется в новые заказы, правится в «Ценах» рядом с браком.

## Деньги

Электроника вносится **на весь заказ**: «Кол-во, шт» умножает только
печать. Три одинаковых устройства — «ESP32 × 3», пайка — общей суммой.

- закупка компонентов `components_purchase = Σ qty × unit_cost`;
- компоненты для клиента `components_cost = components_purchase × (1 + markup/100)`;
- цена = печать (материал + время + брак + реверс, как сейчас)
  + `components_cost` + `soldering_price` + `firmware_price`;
- брак — только от печати;
- если `has_print = 0`, печатная часть равна нулю (поля печати не
  учитываются, даже если что-то заполнено); если `has_electronics = 0` —
  то же для электроники;
- себестоимость (`orders.cost`) = пластик по закупке + `components_purchase`;
- прибыль = цена − себестоимость.

`db.expense()` получает закупку компонентов отдельным аргументом;
`_recalc_costs()` (после смены закупочных цен пластика) складывает её из
`order_components`, чтобы пересчёт не терял компоненты.

`pricing.calc_price()` получает дополнительные необязательные аргументы
(есть печать / есть электроника, список компонентов, наценка, пайка,
прошивка) и возвращает новые ключи: `components_cost`,
`components_purchase`, `soldering_cost`, `firmware_cost`. Вызовы без
новых аргументов работают как раньше. Удобная обёртка
`pricing.calc_order(order)` считает по строке заказа из базы, а
`recalc_order_price()` использует её.

## Экраны

### Новый заказ и карточка заказа

- У секции «Печать» — переключатель в шапке; при выключенном поля
  печати скрыты. В новом заказе по умолчанию включён.
- Новая секция «Электроника» (иконка микросхемы) со своим
  переключателем, по умолчанию выключена. Внутри:
  - строки компонентов: «Название» (с подсказками из прошлых заказов,
    выбор подставляет цену), «Кол-во», «Закупка за шт, ₽», сумма строки,
    кнопка удаления; кнопка «+ Компонент»;
  - «Наценка на компоненты, %», «Пайка и сборка, ₽»,
    «Программирование (прошивка), ₽».
- Общий виджет строк компонентов — в отдельном модуле
  `app/components_editor.py`, используется обоими экранами.
- Хотя бы одна часть должна быть включена — иначе ошибка при создании.
- «Итого»: добавляются строки «Компоненты», «Пайка и сборка»,
  «Программирование» (только ненулевые). Блок прибыли: «Пластик по
  закупке» (если есть печать), «Компоненты по закупке» (если есть
  электроника), «Прибыль».
- В карточке правки сохраняются по уходу из поля, как остальные поля, и
  цена пересчитывается так же, как при правке веса/часов.
- Списание пластика показывается только если в заказе есть печать.

### Список заказов

- Рядом с номером — значки частей: принтер (печать) и микросхема
  (электроника).
- Подзаголовок для электроники без описания — первые компоненты.
- Поиск находит заказ и по названию компонента.

### Прочее

- «Цены»: поле «Наценка на компоненты, %».
- Статистика: подпись в виджете прибыли «себестоимость (пластик +
  компоненты)»; цифры уже из `orders.cost`.
- Экран загрузки: подпись «заказы: печать и электроника».

## PDF для клиента

- «Детали заказа»: строки печати (материал, цвет, вес, время, брак,
  количество) — только если есть печать; при электронике — строка
  «Электроника: N компонентов».
- «Из чего складывается цена»: после строк печати — по строке на
  компонент: «ESP32-WROOM», «2 шт × 540 ₽» (цена для клиента, с
  наценкой; закупка и % не показываются), затем «Пайка и сборка» и
  «Программирование (прошивка)». Сумма строк по-прежнему ровно равна
  цене заказа (существующая логика округления/«Скидки»).

## Смета (Excel) и выгрузка (Google Таблица / Excel)

- Смета: новые колонки «Компоненты (закупка)», «Пайка», «Прошивка»;
  «Себестоимость (пластик)» → «Себестоимость» (пластик + компоненты).
  «Итоги»: строки «Компоненты по закупке», «Пайка», «Прошивка».
- Выгрузка «Заказы»: колонки «Электроника» (да/нет), «Компоненты
  (закупка)», «Пайка», «Прошивка».

## Проверка

- Тесты: расчёт цены/себестоимости с компонентами, наценкой и
  выключенными частями; миграция старой базы (цены и себестоимость не
  меняются); перенос/удаление компонентов с заказом; подсказки
  компонентов; строки PDF (сумма = цена); колонки сметы; сборка экранов.
- Полный прогон `pytest`, сборка exe (версия 1.10.0), перед заменой —
  копия `orders.backup-before-1.10.0.db`.
