# Mochi Desktop — отказ от Telegram, экспорт в Excel, синхронизация с Google Таблицами

Дата: 2026-09-24

## Контекст

Mochi Desktop сейчас — панель поверх `orders.db`, которую по задумке мог
делить с ботом `bot.py` (aiogram, приём заказов в Telegram). Владелец решил,
что бот больше не нужен: всё ведение заказов идёт только через приложение,
данные должны находиться исключительно на его ПК. Дополнительно нужны:
выгрузка всех данных в Excel по кнопке и постоянная синхронизация тех же
данных в Google Таблицу в облаке (владелец подтвердил готовность один раз
настроить служебный Google-аккаунт для этого).

## Решение

### 1. Полный отказ от Telegram

Удаляются: `bot.py`, `start.bat` (лаунчер бота), `app/telegram_files.py`
(скачивание вложений через Bot API), зависимость `aiogram`. Из карточки
заказа убирается кнопка «Скачать» для вложений с `source="telegram"` —
такие вложения (если остались от заказов, созданных ещё через бота)
показываются в списке без возможности повторно скачать файл, только
удалить. `httpx` тоже убирается из зависимостей — он был нужен только для
скачивания из Telegram.

`orders.db` остаётся единственным источником данных, но использует его
теперь только один процесс (само приложение) — обоснование для WAL-режима
и live-sync внутри одного процесса не исчезает (они продолжают
синхронизировать разные окна/экраны приложения между собой), но
межпроцессный сценарий «бот + приложение» больше не актуален.

### 2. Экспорт в Excel

Новый модуль `app/export.py` — единый источник данных для обеих фич этого
плана (экспорт и облачная синхронизация): три функции, которые читают
`db.py`/`pricing.py` и возвращают обычные списки строк (первая строка —
заголовки), без знания о формате вывода:

```python
build_orders_sheet() -> list[list]     # ID, Клиент, Контакт, ... Создан
build_customers_sheet() -> list[list]  # ID, Имя, Контакт, Заметки, Заказов, Оплачено, Долг, Создан
build_prices_sheet() -> list[list]     # материалы + пустая строка + ставки, одним листом
build_all_sheets() -> dict[str, list[list]]  # {"Заказы": ..., "Клиенты": ..., "Цены": ...}
```

`app/excel_writer.py` берёт `build_all_sheets()` и пишет `.xlsx` через
`openpyxl` — по одному листу на ключ словаря. Кнопка «Экспорт в Excel»
добавляется в верхнюю часть `NavigationRail` (рядом с переключателем темы),
по клику открывает системный диалог сохранения (`FilePicker.save_file`),
результат — короткий snack-bar об успехе/ошибке.

### 3. Автосинхронизация с Google Таблицами

Новый модуль `app/sheets_sync.py` — использует тот же `build_all_sheets()`,
но пишет через Google Sheets API (`google-api-python-client` + `google-auth`
+ `google-auth-httplib2`, аутентификация служебным аккаунтом). При первом
запуске синхронизации модуль сам проверяет, что в целевой таблице
существуют листы «Заказы», «Клиенты», «Цены», и создаёт недостающие —
владельцу не нужно вручную готовить листы, только сам файл-таблицу и
доступ для сервисного аккаунта.

Настройка через `.env`: `GOOGLE_SHEET_ID` (ID из ссылки на таблицу) и
`GOOGLE_SERVICE_ACCOUNT_FILE` (путь к скачанному JSON-ключу). Если хотя бы
одна переменная не задана — синхронизация тихо не выполняется, никакой
ошибки пользователю не показывается: приложение обязано работать полностью
автономно без Google так же, как сейчас работает без Telegram.

Триггер — тот же механизм, что уже используется для live-sync между экранами
приложения: `app/main.py`'s `on_db_changed()` (срабатывает через
`LiveSync`, интервал 3 секунды, только при реальном изменении в БД)
дополнительно запускает `sheets_sync.sync_in_background()` — синхронизация
идёт в отдельном потоке, чтобы не блокировать интерфейс. Каждый вызов
полностью перезаписывает все три листа (`values.clear` + `values.update`)
— то же самое допущение о размере данных (десятки/сотни строк), что уже
принято для локального Excel-экспорта, никакой инкрементальной синхронизации.

Ошибки синхронизации (нет сети, неверный ключ, нет доступа к таблице) —
логируются (`logging.warning`), но не показываются пользователю
всплывающим окном: это фоновый, не инициированный пользователем процесс,
и он не должен мешать работе с заказами. Ручной кнопки «Синхронизировать
сейчас» не делаем — только автоматика по изменениям.

## Тестирование

- `app/export.py` — тесты на `temp_db` с заполненными заказом/клиентом/
  материалом, проверяющие точное содержимое возвращаемых строк.
- `app/excel_writer.py` — запись во временный `.xlsx`, чтение обратно тем
  же `openpyxl` и проверка листов/ячеек.
- `app/sheets_sync.py` — `google-api-python-client`'овский клиент мокается
  (подмена `_build_service()`), проверяется, что `sync_now()` вызывает
  `clear`/`update` с ожидаемыми диапазонами и данными; отдельно —
  `is_configured()` на пустых/заполненных переменных окружения.
- Ручная проверка: приложение запускается и работает без `.env` вовсе
  (никакого краша из-за отсутствующих Google/Telegram переменных); кнопка
  экспорта создаёт корректный `.xlsx`, открываемый в реальном Excel.

## Вне рамок (не делаем сейчас)

- Ручная кнопка «Синхронизировать сейчас» — только автоматика.
- Визуальный индикатор состояния синхронизации (последний успех/ошибка) —
  только логирование.
- OAuth-вход личным аккаунтом Google как альтернатива служебному аккаунту.
- Импорт данных обратно из Excel/Google Таблиц в приложение — только
  выгрузка в одну сторону.
